\subsection*{System Architecture}

\subsubsection*{Architectural Philosophy: Decoupled Offline Pipeline and Live Serving}

The system is strictly partitioned into two decoupled subsystems that interact exclusively through
persisted storage contracts:

\begin{itemize}
    \item \textbf{The Offline Content \& Knowledge Pipeline (Heavy AI/ML):}
    \begin{sloppypar}
    \begin{itemize}
        \item Ingests raw textbook PDFs via MinerU and cleans extraction outputs via \texttt{post\_process\_book}.
        \item Formats faithful structurally tagged markdown via \texttt{document-rewriter} (HuatuoGPT-o1-72B).
        \item Executes multimodal figure captioning (\texttt{Qwen2.5-VL-7B}), diagram leader-line detection (\texttt{MedGemma + UNet}), biomedical entity linking to UMLS/SNOMED CT (\texttt{scispaCy}, \texttt{SapBERT/FAISS}), and 27-relation knowledge graph construction (\texttt{knowledge-graph-pipeline}).
        \item Synthesizes validated, graph-grounded MCQs with open-world distractor safety (\texttt{medkg/mcq.py}).
        \item Requires CUDA/MPS GPU hardware, PyTorch, Transformers, FAISS, and isolated Python runtimes.
        \item Produces clean, validated relational tables in PostgreSQL (\texttt{mcq\_questions}) and semantic RDF graphs (\texttt{graph.nq}).
    \end{itemize}
    \end{sloppypar}

    \item \textbf{The Live Serving Layer (FastAPI + iPadOS):}
    \begin{itemize}
        \item High-throughput, CPU-bound REST API built on FastAPI and Uvicorn.
        \item \textbf{Zero PyTorch or Transformers runtime dependencies} --- the serving layer
              never loads model weights, eliminating GPU hosting costs, cold-start latency, and
              out-of-memory crashes on web workers.
        \item Backed by PostgreSQL for immutable question content and Neo4j for event-sourced
              student interaction history, spaced repetition scheduling, and topic mastery.
        \item Real-time personalization executes directly on the student's iPad using an
              on-device Bayesian Knowledge Tracing (BKT) engine.
    \end{itemize}
\end{itemize}

\subsubsection*{Service Layer \& Component Decomposition}

\textbf{Backend Architecture} (\texttt{intelligent-tutoring-system-for-medical-student}):

\begin{itemize}
    \item \textbf{\texttt{app.main}:} Application entry point; installs middleware stack, CORS,
          SlowAPI rate limiting, and exception handlers.
    \item \textbf{\texttt{app.auth\_middleware}:} Inspects every request against a strict regex
          path allowlist; resolves opaque Bearer tokens to \texttt{student\_id} via Neo4j.
    \item \textbf{\texttt{app.errors}:} Formats all HTTP, validation, and driver exceptions into
          a unified contract: \verb|{"error": {"code": "...", "message": "...", "details": [...]}}|.
    \item \textbf{\texttt{src.student\_kg}:} Graph driver and node primitives for student records,
          streak calculations, gamified energy balances, and auth sessions.
    \item \textbf{\texttt{src.quiz}:} Database bank queries, session tracking, answer recording,
          spaced-repetition schedules, and Baum-Welch EM parameter fitting.
    \item \textbf{\texttt{src.flashcards}:} Flashcard generation from questions, 4-tier rating
          logging, and due-review queues.
    \item \textbf{\texttt{src.captioning}:} Vision-language captioning using Qwen2.5-VL-7B.
    \item \textbf{\texttt{src.diagram\_processing}:} MedGemma 4B diagram classification and U-Net leader-line detection.
    \item \textbf{\texttt{src.post\_process\_book}:} Deterministic MinerU extraction cleanup, publisher attribution removal, dash normalization, and page mapping.
\end{itemize}

\textbf{Frontend Architecture} (\texttt{personalized-learning-ios}):

\begin{itemize}
    \item \textbf{Pattern:} MVVM (Model-View-ViewModel) + Protocol-driven Networking.
    \item \textbf{\texttt{App} Layer:} Application lifecycle, root state routing
          (\texttt{ContentView}), and navigation container (\texttt{RootView}).
    \item \textbf{\texttt{Core} Layer:}
    \begin{itemize}
        \item \textit{Networking:} \texttt{APIClient} implementing \texttt{APIClientProtocol},
              \texttt{APIConfig}, \texttt{APIError}, and custom ISO8601 date decoding.
        \item \textit{Persistence:} \texttt{KeychainStore} (secure credential store),
              \texttt{SessionManager} (session token façade), and \texttt{BKTStore}
              (on-device Bayesian Knowledge Tracing engine).
        \item \textit{UI:} Global typography, palette tokens (\texttt{Theme}),
              \texttt{SidebarView}, and \texttt{TopBarView}.
    \end{itemize}
    \item \textbf{\texttt{Features} Layer:} Encapsulated feature domains --- \textit{Auth},
          \textit{Dashboard}, \textit{Quiz}, \textit{Flashcard}, \textit{Subjects},

\subsubsection*{Storage \& Graph Topology}

The persistence model leverages PostgreSQL for relational data and Neo4j for event-sourced
graph data.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\linewidth]{images/flowcharts/mermaid_graph_schema.pdf}
    \caption{Neo4j Student Knowledge Graph Schema: nodes, relationships, and property contracts.}
\end{figure}

Key graph design rules:

\begin{enumerate}
    \item \textbf{Event Sourcing:} Every student interaction creates an immutable
          \texttt{InteractionEvent} node linked in chronological order via \texttt{:NEXT} edges
          and grouped under \texttt{:QuizSession} / \texttt{:FlashcardSession} via
          \texttt{:HAS\_ANSWER}.
    \item \textbf{Mutable Schedules as Edges:} Spaced repetition schedules are stored directly
          on the \texttt{(Student)-[:REVIEWING]->(Question)} edge (quiz) and the
          \texttt{Flashcard} node (flashcards), updating deterministically upon each submission.
    \item \textbf{Mastery Persistence:} The \texttt{:MASTERS} edge represents the student's
          on-device BKT estimate ($p_{\text{know}}$), synchronised asynchronously via
          \texttt{PUT /quiz/mastery}.
    \item \textbf{Relational Question Isolation:} The \texttt{Question} node in Neo4j contains
          \textbf{only} \texttt{uid}. Stem text, options, explanations, and diagrams reside in
          PostgreSQL to protect graph traversal performance.
\end{enumerate}

\textbf{Why Opaque Bearer Tokens (Not JWT)?}

JWTs cannot be instantly revoked without a distributed blacklist. Storing a SHA-256 hashed
token in Neo4j allows instantaneous server-side revocation on logout
(\texttt{revoked\_at = datetime()}) while keeping raw tokens out of the database.

\subsection*{End-to-End Application Flows}

\subsubsection*{Flow 1: Complete System End-to-End Dataflow}

The application architecture coordinates three decoupled subsystems spanning offline content preparation, batch parameter estimation, and real-time interactive learning:

\begin{enumerate}
    \item \textbf{Offline Content Ingestion \& AI Generation:} Medical textbook PDFs are parsed via MinerU (\texttt{notebooks/parse\_books.ipynb}) to extract layout blocks and content streams, cleaned deterministically via \texttt{src/post\_process\_book} to produce clean markdown and page mappings, and structured via \texttt{document-rewriter} into tagged study documents. The \texttt{knowledge-graph-pipeline} (\texttt{medkg}) executes an 8-stage biomedical knowledge graph extraction (scispaCy, SapBERT, HuatuoGPT-o1-72B, 14 relation guards, and OWL-RL reasoning). Graph-grounded MCQ synthesis (\texttt{medkg/mcq.py}) generates single-best-answer questions directly from asserted semantic triples with open-world distractor safety and batch LLM stem phrasing, populating PostgreSQL (\texttt{mcq\_questions}). Multimodal textbook diagrams and figures are processed via \texttt{Qwen2.5-VL-7B} captioning and \texttt{MedGemma + UNet} leader-line detection.
    \item \textbf{Bayesian Knowledge Tracing (BKT) Parameter Training:} Student interaction events (\texttt{:QUIZ\_ANSWER}) recorded in Neo4j are pooled for global parameter fitting. The server executes the Baum-Welch Expectation-Maximisation (EM) algorithm (\texttt{src/quiz/bkt\_fit.py}) to update population-wide transition, slip, and guess probabilities, exposing them through \texttt{GET /quiz/mastery/params}.
    \item \textbf{Live Student Learning Interaction:} The iPadOS client authenticates with the FastAPI backend, caching session tokens in Keychain. Students engage with interactive Quiz and Flashcard modules with sub-15\,ms instant feedback, on-device Bayesian mastery updates, and asynchronous graph persistence to Neo4j.
\end{enumerate}

\subsubsection*{Flow 2: Student Authentication \& Session Lifecycle}

The iPadOS client manages student identity through an opaque Bearer token architecture:

\begin{sloppypar}
\begin{enumerate}
    \item \textbf{Registration \& Login:} The student submits credentials via \texttt{POST /students/login} or \texttt{POST /students/register}. The backend matches or creates the \texttt{:Student} node in Neo4j, mints a 32-byte cryptographic token (\texttt{secrets.token\_urlsafe(32)}), computes its SHA-256 hash, and stores a \texttt{:Session} node with a 30-day expiration timestamp (\texttt{expires\_at}).
    \item \textbf{Secure Client Storage:} The raw token is returned to iPadOS and stored in \texttt{KeychainStore} using the Apple Security framework, while \texttt{SessionManager} publishes the active authentication state.
    \item \textbf{Middleware Verification:} Subsequent HTTP requests provide the token via the \texttt{Authorization:}\allowbreak\ \texttt{Bearer <token>} header. \texttt{SessionAuthMiddleware} intercepts requests, computes the SHA-256 hash, and performs a single Cypher lookup against Neo4j to confirm the session is unrevoked and unexpired, injecting \texttt{student\_id} into \texttt{request.state}.
\end{enumerate}
\end{sloppypar}

\begin{enumerate}
    \item \textbf{Topic Configuration \& Adaptive Weighting (Figure~\ref{fig:quiz_choose_topic}, \ref{fig:quiz_preview}):} The student selects up to three medical topics via \texttt{GET /quiz/topics}. When creating the session (\texttt{POST /quiz/topics/\{path\}/sessions}), the quiz builder generates a test set (e.g., 10 questions) with topic distribution weighted inversely proportional to the student's current Bayesian mastery estimate ($\propto 1 - p_{\text{know}}$), ensuring focused remediation on weak areas. Students can toggle \textit{Review Mode} to receive immediate explanatory feedback after each item.
    \item \textbf{Option Selection \& Instant Grading (Figure~\ref{fig:quiz_question}):} The student selects an answer option and self-reports a metacognitive confidence level (\textit{Confident / Unsure / Guessing}). \texttt{POST /quiz/questions/\{uid\}/check} is a public, stateless endpoint that evaluates the option against an in-memory sanitized question bank---returning \texttt{correct}, \texttt{correct\_index}, and a verified clinical \texttt{explanation} with textbook section provenance in sub-15\,ms. Correct and incorrect choices are immediately color-coded in the UI (green checkmark vs.\ red cross).
    \item \textbf{On-Device BKT Update:} Immediately upon evaluation, \texttt{BKTStore.record()} on iPadOS computes the updated Bayesian posterior mastery $p_{\text{know}}$ using confidence-stratified slip and guess probabilities ($p_{\text{slip}}[c], p_{\text{guess}}[c]$). The updated estimate is written synchronously to local \texttt{UserDefaults} and dispatched asynchronously to Neo4j via a background \texttt{PUT /quiz/mastery} request.
    \item \textbf{Stateful Log Commit \& Spaced Repetition:} When advancing to the next question, the client issues an authenticated \texttt{POST /quiz/questions/\{uid\}/log} request. The backend commits an immutable \texttt{:QUIZ\_ANSWER} event linked to the active \texttt{:QuizSession} and updates the spaced-repetition schedule on the \texttt{(Student)-[:REVIEWING]->(Question)} edge.
    \item \textbf{Quiz Completion \& Gamification:} \texttt{POST /quiz/sessions/\{id\}/end} finalises the session, aggregates score metrics, updates the student's daily activity streak, and awards $+5$ Energy currency in Neo4j.
\end{enumerate}

\subsubsection*{Flow 5: Adaptive Knowledge Tracing \& Personalization Loop}

    \caption{Curriculum Navigation and Explainable Bayesian Mastery: (a) Subject overview browser displaying aggregate topic mastery percentages, (b) Subject detail view rendering subtopic mastery status badges, and (c) Explainable AI (XAI) diagnostic modal detailing confidence discounting, recent attempt trajectory, and Bayesian posterior updating.}
    \label{fig:mastery_flow_screens}
\end{figure}

\begin{enumerate}
    \item \textbf{Server-Side Population Parameter Fitting (Periodic Batch):} Interaction sequences are extracted from pooled \texttt{:QUIZ\_ANSWER} nodes in Neo4j. The Baum-Welch EM script (\texttt{src/quiz/bkt\_fit.py}) executes Forward-Backward rescaling (E-step) and expectation maximisation (M-step) to derive global parameters: $p_{\text{init}}$, $p_{\text{transit}}$, and confidence-conditioned $p_{\text{slip}}(c)$ and $p_{\text{guess}}(c)$. Fitted parameters are cached and exposed via \texttt{GET /quiz/mastery/params}.
    \item \textbf{Client-Side Real-Time Knowledge Tracing (iPadOS):} On application launch, \texttt{BKTStore} refreshes and caches population parameters. When the student answers a question with confidence $c$, \texttt{BKTStore} computes the closed-form Bayesian posterior:
    \begin{equation}
        p(L_t \mid y_t, c) = \frac{p(L_{t-1}) \cdot P(y_t \mid L_t, c)}{P(y_t \mid c)}
    \end{equation}
    and applies the transition prior $p(L_{t+1}) = p(L_t \mid y_t, c) + (1 - p(L_t \mid y_t, c)) p_{\text{transit}}$. The resulting $p_{\text{know}}$ is stored in local storage and dispatched asynchronously to Neo4j via \texttt{PUT /quiz/mastery}.
    \item \textbf{Curriculum Mastery Navigation (Figure~\ref{fig:subjects_view}, \ref{fig:subject_detail_view}):} In \texttt{SubjectsView}, individual topic masteries are aggregated across medical subject modules (e.g., \textit{Amino Acids \& Peptides (34\%)}, \textit{Biosynthesis of Fatty Acids (42\%)}). In \texttt{SubjectDetailView}, fine-grained subtopics display item counts and state labels (\textit{Needs Work}, \textit{Review Due}, \textit{Mastered}) based on thresholded $p_{\text{know}}$ values.
    \item \textbf{Explainable AI (XAI) Diagnostic Modal (Figure~\ref{fig:topic_breakdown_view}):} To demystify the machine learning model for learners, tapping the info badge opens the \textit{Topic Breakdown} modal. This interface explains how the mastery level is calculated, illustrates recent attempt trajectories (e.g., \textit{Correct · Unsure · $+7\%$}), and explains why guessing is discounted: \textit{``Recent attempts suggest this isn't solid yet. This score already discounts lucky guesses, so it reflects real gaps---a good candidate for focused practice.''}
    \item \textbf{Downstream Personalization Delivery:}
    \begin{itemize}[leftmargin=*]
        \item \textit{Weighted Quiz Selection:} Multi-topic quizzes sample questions with weights inversely proportional to topic mastery ($\propto 1 - p_{\text{know}}$).
        \item \textit{Flashcard Weak-Topic Infill:} Practice decks prioritize review cards from topics exhibiting the lowest mastery scores.
        \item \textit{Adaptive Nudges \& Progress:} The backend \texttt{GET /students/me/nudge} endpoint inspects \texttt{:MASTERS} edges to surface high-priority study recommendations on the dashboard.
    \end{itemize}
\end{enumerate}

\subsubsection*{Flow 6: Offline Ingestion \& Graph-Grounded MCQ Generation Pipeline}

The offline ingestion pipeline converts unstructured medical textbooks into formal knowledge graphs and verified multiple-choice questions across five sequential stages:

\begin{sloppypar}
\begin{enumerate}
    \item \textbf{Stage 1: Parsing \& Extraction:} The MinerU CLI and notebook (\texttt{notebooks/\allowbreak parse\_books.ipynb}) process raw textbook PDFs to extract layout bounding boxes (\texttt{\_middle.json}), content streams (\texttt{\_content\_list.json}), and embedded anatomical figures.
    \item \textbf{Stage 2: Deterministic Book Cleaning (\texttt{src/\allowbreak post\_process\_book}):} Cleans MinerU output by stripping image blocks, headers/footers, and publisher citation parentheticals while preserving paragraph body text, list structures, tables, mathematical formulas, and inline figure mentions. Outputs \texttt{<chapter>.cleaned.md} and \texttt{<chapter>.page\_map.json}.
    \item \textbf{Stage 3: Structural Document Rewriting (\texttt{document-rewriter}):} Under strict faithfulness constraints, carries over textbook prose verbatim into structured XML-like study markdown (\texttt{<doc>}, \texttt{<con>}, \texttt{<fig>}, \texttt{<tbl>}), resolving in-document cross-references into \texttt{<figref>}/\texttt{<tblref>} and calling HuatuoGPT-o1-72B exclusively for the document \texttt{<topic>} line.
    \item \textbf{Stage 4: Domain Knowledge Graph Construction (\texttt{knowledge-graph-\allowbreak pipeline}):} The 8-stage \texttt{medkg} engine executes scispaCy NER, SapBERT entity linking with UMLS semantic type label correction, HuatuoGPT-o1-72B relation and modifier extraction, 14 deterministic relation guards, post-coordination modifier minting, RDF quad assertion, and OWL-RL reasoning.
    \item \textbf{Stage 5: Graph-Grounded MCQ Generation \& Database Population (\texttt{medkg/\allowbreak mcq.py}):} Synthesizes single-best-answer MCQs directly from asserted semantic triples across 13 core clinical predicate templates. Enforces 3-tier distractor ranking with open-world multi-graph blocklisting and batch LLM stem phrasing (\texttt{phrase\_items}) with deterministic template fallback. Validated questions are committed to PostgreSQL (\texttt{mcq\_questions}).
\end{enumerate}
\end{sloppypar}

\subsubsection*{Flow 7: Domain Knowledge Graph (medkg) Pipeline}

The domain knowledge graph pipeline constructs a formal, ontology-grounded biomedical semantic graph across eight stages:

\begin{sloppypar}
\begin{enumerate}
    \item \textbf{Stage 1 (Parse):} Ingests semantically tagged Markdown containing clinical inline annotations (\texttt{<con>}, \texttt{<def>}, \texttt{<clin>}), validating character spans and emitting normalized text alongside offset-anchored IR chunks.
    \item \textbf{Stage 2 \& 3 (NER, Entity Linking \& Relation Extraction):} Executes scispaCy NER (\texttt{en\_ner\_bc5cdr\_md}, \texttt{en\_ner\_bionlp13cg\_md}) and SapBERT dense entity linking via FAISS ($\cos \ge 0.70$). UMLS semantic types from \texttt{semantic\_types.json} dynamically re-derive span ontology labels to prevent domain classification errors before HuatuoGPT-o1-72B extracts 27-relation medical triples and qualifiers.
    \item \textbf{Guard Layer (14 Deterministic Guards):} Audits all extracted candidates against directional connectives, governed roles, and evidence scope, demoting suspect relations to \texttt{polarity = "uncertain"}.
    \item \textbf{Stage 4 (Post-coordination):} Mints scoped \texttt{:INSTANCE} nodes to model complex clinical modifiers (especially \texttt{deviation} modifiers such as deficiency or excess on substances) to preserve clinical semantics without combinatorial ontology explosion.
    \item \textbf{Stage 5 (Multimodal Grounding):} Handles figure depiction structures, strictly firewalling visual descriptions so that figure captions never become ungrounded clinical facts.
    \item \textbf{Stage 6 (RDF Assertion):} Serializes extracted assertions into W3C RDF Named Quads (\texttt{<subject> <predicate> <object> <graph>}) partitioned per document and section, with provenance metadata.
    \item \textbf{Stage 7 (OWL-RL Reasoning):} Applies deterministic OWL 2 RL inference rules in-process via \texttt{owlrl} to materialize implicit taxonomic, inverse, and transitive relationships into \texttt{urn:graph:inferred}.
    \item \textbf{Stage 8 (Serving \& Subsetting):} Exports the reasoned knowledge base as N-Quads, hosts a SPARQL query endpoint, and supports document/section graph subsetting for downstream MCQ generation and semantic exploration.
\end{enumerate}
\end{sloppypar}

A critical architectural achievement is that \textbf{the live FastAPI serving application
performs zero model inference at runtime}:

\begin{enumerate}
    \item \textbf{CPU-Only Bound:} The production server requires only standard CPU instances

    \item \textbf{Instant Latency:} Response times for \texttt{/quiz/questions},
          \texttt{/quiz/check}, and \texttt{/quiz/log} remain sub-15\,ms because they execute

          CUDA version mismatches, or VRAM exhaustion.
\end{enumerate}

\subsection*{Mathematical Foundations \& Algorithms}

\subsubsection*{Bayesian Knowledge Tracing (BKT) with Confidence Emissions}

Standard BKT models a student's latent knowledge of a specific medical topic as a 2-state
Hidden Markov Model:

\begin{itemize}
    \item \textbf{State 0:} \textit{Doesn't Know}
    \item \textbf{State 1:} \textit{Knows}
\end{itemize}

To account for metacognitive awareness, emission probabilities $p_{\text{slip}}$ and
$p_{\text{guess}}$ are conditioned on the student's self-reported confidence
$c \in \{\text{confident},\,\text{unsure},\,\text{guessing}\}$:

\begin{center}
\begin{tabular}{|l|c|c|>{\raggedright\arraybackslash}p{0.48\linewidth}|}
\hline
\textbf{Confidence ($c$)} & $p_{\text{slip}}$ & $p_{\text{guess}}$ & \textbf{Pedagogical Interpretation} \\
\hline
\textbf{Confident} & $0.05$ & $0.10$ & Confident-wrong strongly penalises $p_{\text{know}}$ as a misconception. \\
\hline
\textbf{Unsure} & $0.10$ & $0.25$ & Standard baseline BKT behaviour. \\
\hline
\textbf{Guessing} & $0.30$ & $0.50$ & Correct guess does not falsely award mastery. \\
\hline
\end{tabular}
\end{center}

\textbf{Observation Update (Bayes Rule):} Given prior mastery $p_{\text{know}}$ and observation
$O_t \in \{\text{Correct},\,\text{Incorrect}\}$ with confidence $c$:

\[
O_t = \text{Correct}: \quad
p_{\text{know}}^{\text{post}} = \frac{p_{\text{know}} \cdot (1 - p_{\text{slip}}[c])}
  {p_{\text{know}} \cdot (1 - p_{\text{slip}}[c]) + (1 - p_{\text{know}}) \cdot p_{\text{guess}}[c]}
\]

\[
O_t = \text{Incorrect}: \quad
p_{\text{know}}^{\text{post}} = \frac{p_{\text{know}} \cdot p_{\text{slip}}[c]}
  {p_{\text{know}} \cdot p_{\text{slip}}[c] + (1 - p_{\text{know}}) \cdot (1 - p_{\text{guess}}[c])}
\]

\textbf{Learning State Transition} (accounting for knowledge acquisition during the attempt):
\[
p_{\text{know}}^{\text{next}} = p_{\text{know}}^{\text{post}} + (1 - p_{\text{know}}^{\text{post}}) \cdot p_{\text{transit}}
\]

\subsubsection*{Baum-Welch Expectation-Maximisation (EM) Parameter Fitting}

Implemented in \texttt{src/quiz/bkt\_fit.py}, the Baum-Welch EM algorithm fits optimal global
parameters across all pooled student sequences:

\begin{enumerate}
    \item \textbf{E-Step (Forward-Backward Rescaling):} Compute smoothed posterior state
          probabilities $\gamma_t(i) = P(S_t = i \mid \mathbf{O})$ and transition probabilities
          $\xi_t(0,1) = P(S_t = 0,\, S_{t+1} = 1 \mid \mathbf{O})$.
    \item \textbf{M-Step (Closed-Form Aggregation):}
\end{enumerate}

\[
p_{\text{init}} = \frac{1}{|\mathcal{S}|} \sum_{s \in \mathcal{S}} \gamma_0^{(s)}(1)
\qquad
p_{\text{transit}} = \frac{\sum_{s} \sum_{t} \xi_t^{(s)}(0,1)}{\sum_{s} \sum_{t} \gamma_t^{(s)}(0)}
\]

\[
\forall c:\;
p_{\text{slip}}[c] = 1 - \frac{\sum_{s} \sum_{t:\,O_t=\text{Correct},\,C_t=c} \gamma_t^{(s)}(1)}
  {\sum_{s} \sum_{t:\,C_t=c} \gamma_t^{(s)}(1)}
\qquad
p_{\text{guess}}[c] = \frac{\sum_{s} \sum_{t:\,O_t=\text{Correct},\,C_t=c} \gamma_t^{(s)}(0)}
  {\sum_{s} \sum_{t:\,C_t=c} \gamma_t^{(s)}(0)}
\]

\subsubsection*{Dual-Track Spaced Repetition Scheduling}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\linewidth]{images/flowcharts/mermaid_spaced_repetition.pdf}
    \caption{Dual-track spaced repetition: Quiz track (REVIEWING edge) and Flashcard track
             (SuperMemo self-rating intervals).}
\end{figure}

The two tracks use distinct scheduling mechanics:

\begin{itemize}
    \item \textbf{Quiz Track} (\texttt{(Student)-[:REVIEWING]->(Question)} edge): Correct +
          Confident $\Rightarrow$ \texttt{streak += 1}, \texttt{interval = min(60, interval$\times$2)}.
          Wrong or low-confidence $\Rightarrow$ reset: \texttt{streak = 0}, \texttt{interval = 1}.
    \item \textbf{Flashcard Track} (\texttt{Flashcard} node):
          \textit{Again} $\Rightarrow$ reset to 1 day;
          \textit{Hard} $\Rightarrow$ interval $\times$ 1.2;
          \textit{Good} $\Rightarrow$ streak $+1$, interval $\times$ 2.0;
          \textit{Easy} $\Rightarrow$ streak $+1$, interval $\times$ 2.5. All capped at 60 days.
\end{itemize}

\subsubsection*{Gamification Economy: Streaks, Energy \& Nudge Heuristics}

The student learning experience is orchestrated through a gamified habit-loop on the iPadOS dashboard (Figure~\ref{fig:dashboard_screen}), connecting backend persistence in Neo4j to cognitive reinforcement heuristics:

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.88\linewidth]{images/application/dashboard.jpeg}
    \caption{MediQuiz Student Dashboard: Integrating review nudge heuristics (due quiz questions and flashcards), active day streak tracking with recovery prompts, targeted weak-topic remediation cards, and live energy points ledger.}
    \label{fig:dashboard_screen}
\end{figure}

\begin{enumerate}
    \item \textbf{Review Nudge Recommendation Engine (\texttt{GET /students/me/nudge}):}
          Aggregates total due quiz questions and due flashcards across the student's spaced repetition schedules (e.g., \textit{``54 due for review: 28 quiz questions and 26 flashcards''}), identifying the single item with $\min(\texttt{next\_review\_at})$ across both modes to populate the prominent top dashboard reminder banner with a direct one-tap review action.
    \item \textbf{Consecutive Streak Tracking (\texttt{src/student\_kg/streak.py}):}
          Evaluates distinct calendar days in UTC where the student generated at least one \texttt{QUIZ\_ANSWER} or \texttt{FLASHCARD\_\allowbreak REVIEW}. A gap $\geq 2$ days resets \texttt{current\_streak = 0} while \texttt{previous\_streak} retains the broken length, displaying an encouraging prompt (e.g., \textit{``Your 14-day streak ended. Start a new one today''}) alongside a weekly completion calendar.
    \item \textbf{Streak Restoration (\texttt{POST /students/me/streak/restore}):}
          If the student missed exactly 1 day, they spend \textbf{10 Energy} units to bridge the gap and restore their previous streak.
    \item \textbf{Energy Points Ledger (\texttt{src/student\_kg/energy.py}):}
          Earned: $+5$ per Quiz Session completion, $+1$ to $+2$ per Flashcard Review.
          Spent: $-10$ per Streak Restore. The student's live balance (e.g., 158 Energy Points) is permanently visible on the sidebar profile widget.
    \item \textbf{Targeted Weakness Remediation (``Areas to Improve''):}
          The dashboard queries the student's lowest $p_{\text{know}}$ topics from Neo4j (\texttt{:MASTERS} edges) to display high-impact practice cards (e.g., \textit{Parathyroid Hormone Regulation --- Needs Work}) with a direct \textit{Practice Now} CTA button.
\end{enumerate}

\subsection*{Responsible AI Integration}

MediQuiz applies responsible AI principles across three dimensions: user data sovereignty,
content licensing integrity, and transparency in algorithmic decision-making.
Each principle is grounded in concrete system design choices rather than policy statements alone.

\subsubsection*{On-Device Knowledge State}

The student's primary knowledge representation --- the Bayesian posterior mastery
estimate $p_{\text{know}}$ and its underlying attempt history --- is computed and
persisted entirely on the student's own iPad. The BKT update rule executes within
\texttt{BKTStore} in the Swift Standard Library with zero network dependency; the
result is written synchronously to local \texttt{UserDefaults} before any background
sync is dispatched to Neo4j. This means the student retains direct, local custody of
their most sensitive learning signal at all times. No third-party inference endpoint,
cloud ML service, or external model host ever processes individual mastery trajectories.
The server receives only the final scalar $p_{\text{know}}$ value --- not the raw
answer sequence used to derive it --- limiting the exposure of detailed performance data
to the minimum necessary for aggregate parameter fitting.

\subsubsection*{Authorised Content Sources \& Institutional Scope}

All educational content ingested by MediQuiz is sourced exclusively from
AccessMedicine, a licensed medical reference platform whose terms of use are
complied with throughout the pipeline. The ingestion workflow applies strict
faithfulness constraints: \texttt{document-rewriter} carries over textbook prose
verbatim under a ``no paraphrasing'' instruction, and the offline pipeline is operated
on institution-controlled infrastructure rather than third-party cloud services.
Critically, the application is not publicly distributed; it is deployed solely within
the university environment for enrolled medical students in Ciputra University, ensuring that the use of
licensed materials remains within the permitted institutional scope. The question bank
produced from these sources is stored in a private PostgreSQL instance and is not
exposed to external systems or users.

\subsubsection*{Explainable Student Mastery \& Bounded Scope}

Learners are shown the confidence estimate behind each mastery label --- not a
binary pass/fail verdict. The \textit{Topic Breakdown} modal (Figure~\ref{fig:topic_breakdown_view})
surfaces the Bayesian posterior value, the recent attempt trajectory with per-attempt
confidence weighting, and a plain-language explanation of why the estimate is
discounted for lucky guesses (e.g.,\ \textit{``This score already discounts lucky
guesses, so it reflects real gaps''}). The scope of explainability is deliberately
bounded to the learning-progress domain: BKT explains skill-tracking logic only.
The system makes no clinical diagnostic claims, offers no medical advice, and produces
no patient-facing output. Every explanation text is derived from verified textbook
provenance rather than generative LLM inference at serve time, preventing hallucination
of clinical facts during live student interaction.

          \texttt{src/student\_kg/}.
    \item \textbf{Register Router Route:} Add a route handler to
          \texttt{app/routers/students.py} specifying \texttt{@router.post(...)}.
    \item \textbf{Configure Auth Allowlist (If Public):} If unauthenticated, update regex rules
          in \texttt{app/auth\_middleware.py}.
    \item \textbf{Add Tests:} Create corresponding test cases in \texttt{tests/}.
\end{enumerate}

\subsubsection*{Recipe: Adding a New iPadOS Feature / View}

To implement a new feature view (e.g.\ \texttt{BookmarksView}):

{\sloppy
\begin{enumerate}
    \item \textbf{Declare Protocol Method:} Add the \texttt{async} API signature to
          \texttt{Core/\allowbreak Networking/\allowbreak APIClientProtocol.swift}.
    \item \textbf{Implement Network Call:} Implement the method in
          \texttt{Features/\allowbreak Bookmark/\allowbreak BookmarkAPI.swift}
          using \texttt{client.get(...)} or \texttt{client.send(...)}.
    \item \textbf{Build ViewModel:} Create \texttt{BookmarkViewModel} conforming to
          \texttt{ObservableObject} marked \texttt{@MainActor}, holding \texttt{@Published} state
          and injecting \texttt{any APIClientProtocol}.
    \item \textbf{Construct SwiftUI View:} Build the interface in
          \texttt{BookmarkView.swift} observing \texttt{BookmarkViewModel}.
    \item \textbf{Register Navigation:} Add an enum case to \texttt{SidebarItem} in
          \texttt{Core/\allowbreak UI/\allowbreak SidebarView.swift} and wire the switch statement in
          \texttt{App/\allowbreak RootView.swift}.
\end{enumerate}
