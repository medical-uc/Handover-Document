\section*{AI/ML Solution Technical Overview}

\subsection*{Data Collection \& Preprocessing}

\subsubsection*{Data Sources}

\begin{itemize}
    \item \textbf{Medical Textbooks (\texttt{data/textbook/}):}
    \begin{itemize}
        \item \textbf{Source \& Format:} AccessMedicine by McGraw-Hill (PDF, 3 documents, $\sim$700--1000 pages each)
        \item \textbf{Titles:}
        \begin{itemize}
            \item \textit{Ganong's Review of Medical Physiology (27th ed.)}
            \item \textit{Harper's Illustrated Biochemistry}
            \item \textit{Junqueira's Basic Histology: Text and Atlas}
        \end{itemize}
        \item \textbf{Content Structure:}
        \begin{itemize}[itemsep=0pt,topsep=0pt]
            \item Chapter titles, headings, and sub-headings
            \item Paragraph body text and nested list structures
            \item Tables with captions and footnotes
            \item Diagrams and flowcharts
            \item Inline mathematical equations
        \end{itemize}
    \end{itemize}

    \item \textbf{Question Sets (\texttt{data/mcq/}):}
    \begin{itemize}
        \item Pre-made MCQ evaluation packets (\textit{Batch 1}, \textit{Batch 2}) for question validation and benchmarking.
    \end{itemize}
\end{itemize}


\subsubsection*{Data Cleaning}

\noindent Raw PDFs are first extracted by \textbf{MinerU} (in an isolated Python
environment), which produces a structured \texttt{*\_\allowbreak middle.json} block file and associated
\texttt{*\_\allowbreak content\_\allowbreak list.json} per chapter. The \texttt{post\_process\_book} package then cleans
this MinerU output to produce the final text corpus.

\begin{itemize}
    \item Removing irrelevant content blocks: image blocks, running headers/footers, page numbers,
          source attribution lines, ``reproduced/adapted with permission'' phrases, publisher
          citation parentheticals, and entire \textit{Recommended Reading} / \textit{References}
          sections.

    \item Outputs per chapter: \texttt{<basename>\allowbreak.cleaned\allowbreak.md} (full cleaned markdown) and
          \texttt{<basename>\allowbreak.page\_\allowbreak map.json} (character-level and line-level page offsets used
          for downstream retrieval grounding).
\end{itemize}


\subsubsection*{Data Preprocessing}

\noindent After cleaning, the \texttt{.cleaned.md} files pass through two sequential steps
before knowledge-graph construction.

\begin{itemize}
    \item \textbf{Document rewriting:}
          \texttt{rewrite\_medical\_md.py} (\texttt{document-rewriter} repository) reads each
          \texttt{.cleaned.md} chapter and re-emits it as a structurally tagged markdown file.
          Body paragraphs are carried over verbatim into \texttt{<con>} elements; PDF-extraction
          artefacts (non-breaking spaces, soft hyphens, mid-sentence page-break splits) are
          repaired. Inference is limited to one \textbf{HuatuoGPT-o1-72B} call per chapter for
          the \texttt{<topic>} element, which has no source counterpart.

    \item \textbf{Stage 1 parse:}
          The tagged markdown is consumed by Stage~1 of the \texttt{medkg} pipeline
          (\texttt{stage1\_parse.py}), which produces a tag-free normalised text file and a
          structured IR JSON carrying offset-anchored chunks, figures and passages. Chunk kinds
          are \texttt{prose}, \texttt{definition}, \texttt{clinical}, \texttt{summary} and
          \texttt{caption}; only the first four reach Stage~2 extraction.
\end{itemize}


\subsubsection*{Feature Engineering}

\begin{itemize}
    \item \textbf{Context enrichment:} The most specific section heading from each chunk's
          \texttt{section\_path} is prepended to its text before any LLM call, preserving the
          governing medical concept even for short fragment chunks.

    \item \textbf{Medical triple extraction:}
          Stage~2 of the \texttt{medkg} pipeline makes one \textbf{HuatuoGPT-o1-72B} LLM
          call per chunk to extract structured \texttt{\{subject, relation, object\}} triples.
          {\sloppy Relations are constrained to a closed \textbf{27-relation taxonomy} defined in
          \texttt{medkg/ontology\_medschool.json}:
          \texttt{treated\_with}, \texttt{prevented\_by}, \texttt{caused\_by},
          \texttt{finding\_site}, \texttt{associated\_with}, \texttt{present\_in\_patient},
          \texttt{part\_of}, \texttt{located\_in}, \texttt{composed\_of}, \texttt{connects\_to},
          \texttt{secretes}, \texttt{synthesizes}, \texttt{stores}, \texttt{transports},
          \texttt{converts\_to}, \texttt{catalyzes}, \texttt{regulates}, \texttt{stimulates},
          \texttt{inhibits}, \texttt{requires}, \texttt{has\_function}, \texttt{risk\_factor\_for},
          \texttt{complication\_of}, \texttt{diagnosed\_by}, \texttt{adverse\_effect\_of},
          \texttt{contraindicated\_in}, \texttt{has\_mechanism}.
          14 deterministic relation guards then audit every extracted relation before assertion.\par}

    \item \textbf{Distractor engineering:} A two-tier strategy selects wrong answer options.
          Tier 1 performs corpus-level retrieval — for the same \texttt{(topic, relation)} pair,
          other objects seen elsewhere in the corpus serve as plausible distractors.
          Tier 2 falls back to the LLM when Tier 1 yields fewer than 3 candidates. A Pydantic
          \texttt{DistractorSet} validator rejects any distractor that duplicates the correct
          answer.

    \item \textbf{Domain Knowledge Graph:}
          \texttt{medkg/} implements an 8-stage pipeline that builds an RDF knowledge
          graph from the textbook markdown — scispaCy NER, SapBERT/FAISS entity linking to
          UMLS/SNOMED CT, deterministic post-coordination modifier minting (\texttt{INSTANCE}
          nodes), and RDFS/OWL-RL reasoning. This enriches the semantic structure of extracted
          medical entities beyond what the triple-extraction LLM alone can capture.
\end{itemize}

\subsection*{Exploratory Data Analysis}

\begin{itemize}
    \item \textbf{Question bank distribution:}
          The generated question bank (\texttt{question\_bank.json}) contains \textbf{188 validated
          MCQs} spanning medical textbook sections, distributed across three difficulty tiers:
          Tier 1 (Recall), Tier 2 (Application), and Tier 3 (Clinical Vignette Reasoning).

    \item \textbf{Self-critique correction rate:}
          Approximately \textbf{62\% (116 of 188)} questions triggered the automated self-critique
          correction pass (\texttt{valid\_as\_generated: false}), demonstrating that the
          \textit{Critique} and \textit{Corrector} feedback loop is essential for output quality —
          single-pass generation alone was insufficient.

    \item \textbf{MinerU quality diagnostics:}

          {\sloppy \texttt{src/evaluation/mineru\_quality.py} provides reference-free quality metrics for
          raw MinerU output, including garbage-character ratio, empty-block ratio, repeated-character
          runs, and per-block confidence scores. These were used to spot-check extraction quality
          across the five textbook PDFs. \par}

    \item \textbf{Knowledge graph structure:}
          {\sloppy Student interaction data is stored in Neo4j as
          \texttt{(Student)-[:ANSWERED]->(Question)} edges, with a topic hierarchy modelled as
          \texttt{(Topic)-[:SUB\_TOPIC\_OF]->(Topic)} to support spaced-repetition scheduling
          and Bayesian Knowledge Tracing queries.\par}
\end{itemize}

\subsection*{Model Experiment}

\noindent All models are deployed in an \textbf{inference-only} setup — no fine-tuning or
backpropagation during live serving. The list below documents each model's role, architectural
hyperparameters, operational runtime configuration, fallback defaults, and validation mechanisms
across the pipeline:

{\sloppy
\begin{itemize}
    \item \textbf{HuatuoGPT-o1-72B (4-bit)} (\textit{Medical Reasoning LLM})
    \begin{itemize}
        \item \textbf{Role:} Document rewriting and semantic tagging (\texttt{rewrite\_medical\_md.py}); Stage~2 relation and modifier extraction (\texttt{medkg/stage2\_extract.py}); Stage~3 ambiguous concept reranking (\texttt{medkg/stage3\_link.py}).
        \item \textbf{Configuration \& Hyperparameters:}
        \begin{itemize}[itemsep=1pt,topsep=1pt]
            \item \textit{Checkpoint \& Backend:} \texttt{mlx-community/HuatuoGPT-o1-72B-4bit} served via an OpenAI-compatible vLLM/MLX endpoint (\texttt{DEFAULT\_BASE\_URL = "http://jupyter-02.aml1.id.iosda.org:8888"}, default fallback \texttt{http://localhost:8888}).
            \item \textit{Rewriter Sampling:} Section-specific temperatures: $T_{\text{topic}} = 0.30$, $T_{\text{caption}} = 0.15$ (strict factual alignment), $T_{\text{objectives}} = 0.35$, $T_{\text{summary}} = 0.35$, fallback $T = 0.40$; top-$p = 0.90$.
            \item \textit{Rewriter Token Limits:} $\text{max\_tokens} = 1024$ for \texttt{<topic>} and \texttt{<cap>}; $\text{max\_tokens} = 2048$ for \texttt{<obj>}, \texttt{<sum>}, and general completions.
            \item \textit{Stage 2 Extraction:} Greedy decoding ($T = 0.0$, $\text{max\_tokens} = 4096$) with vLLM guided JSON decoding (\texttt{extra\_body=\allowbreak\{"guided\_json": schema\}}).
            \item \textit{Stage 3 Disambiguation:} Greedy decoding ($T = 0.0$, $\text{max\_tokens} = 24$) with guided choice (\texttt{extra\_body=\allowbreak\{"guided\_choice": choices\}}), cached per \texttt{(mention, choices)} tuple.
            \item \textit{Execution \& Resilience:} 900\,s timeout (rewriter) / 300\,s timeout (Stage 2); 4 retries with exponential backoff; 4 concurrent worker threads; SHA-256 payload disk caching; client-side chain-of-thought stripping (\texttt{split\_reasoning} discarding \texttt{\#\# Thinking} and \texttt{<think>} traces); circuit breaker halting after 5 consecutive failures (\texttt{BackendUnavailable}); \texttt{--offline} rule-based fallback.
        \end{itemize}
        \item \textbf{Validation:} Tag-completeness checks; exact-match chunk text grounding; Pydantic schema validation (\texttt{Triple}, \texttt{Modifier}); closed 27-relation taxonomy guards.
    \end{itemize}

    \item \textbf{SapBERT} (\textit{Biomedical Sentence Transformer})
    \begin{itemize}
        \item \textbf{Role:} Stage~3 entity linking to UMLS/SNOMED CT concepts (\texttt{medkg/stage3\_link.py}).
        \item \textbf{Configuration \& Hyperparameters:}
        \begin{itemize}[itemsep=1pt,topsep=1pt]
            \item \textit{Checkpoint \& Pooling:} \texttt{cambridgeltl/SapBERT-from-PubMedBERT-fulltext} ($d = 768$); $[CLS]$ token representation from \texttt{last\_hidden\_state}; unit $L_2$-normalization.
            \item \textit{Index \& Search:} FAISS \texttt{IndexFlatIP} (Exact Inner Product on normalized vectors $\equiv$ Cosine Similarity); candidate retrieval depth $k = 20$; sequence length capped at 32 tokens; batch size 256.
            \item \textit{Thresholds:} Cosine similarity floor $\ge 0.70$ (\texttt{LINK\_CONFIDENCE\_FLOOR = 0.70}); LLM reranker invoked only when top-2 candidate margin $(\text{score}_1 - \text{score}_2) < 0.05$ (\texttt{RERANK\_MARGIN = 0.05}).
            \item \textit{Concurrency Safety:} Native thread pinning (\texttt{MEDKG\_NATIVE\_THREADS = 1}) across OpenMP, PyTorch, and FAISS runtimes to prevent macOS Darwin/BLIS segmentation faults.
            \item \textit{Semantic Typing:} UMLS \texttt{MRSTY.RRF} crosswalk (\texttt{semantic\_types.json}) applying \texttt{SEMANTIC\_TYPE\_PRIORITY} to refine coarse NER labels into canonical ontology span labels.
        \end{itemize}
        \item \textbf{Validation:} Link-confidence distribution; CUI collision detection; semantic type compatibility checks.
    \end{itemize}

    \item \textbf{Qwen3.5-27B / Qwen3.5-9B-OptiQ} (\textit{LLM})
    \begin{itemize}
        \item \textbf{Role:} MCQ question-stem phrasing, distractor evaluation, and automated self-critique loop (\texttt{medkg/mcq.py}).
        \item \textbf{Configuration \& Hyperparameters:}
        \begin{itemize}[itemsep=1pt,topsep=1pt]
            \item \textit{Checkpoint \& Backend:} \texttt{Qwen/Qwen3.5-27B} or \texttt{mlx-community/Qwen3.5-9B-OptiQ-4bit} via OpenAI-compatible endpoint (\texttt{http://localhost:8888/v1}); $T = 0.0$, $\text{max\_tokens} = 4096$, guided JSON schema decoding.
            \item \textit{Batching \& Limits:} Batch size of 10 items per phrasing pass (\texttt{phrase\_items}); maximum stem length capped at 300 characters; 5 options per question (1 key + 4 distractors).
            \item \textit{Distractor Safety Guardrails:} 3-tier open-world exclusion (asserted/inferred/flagged triple blocklist; alternate head-edge prohibition; indefinite stem framing); negative-stem regex guard (\texttt{\_NEGATIVE\_RE}) rejecting negative phrasing to prevent open-world fallacies.
            \item \textit{Self-Critique Cycle:} Automated critique and corrector loop evaluating distractor plausibility and answer leakage.
        \end{itemize}
        \item \textbf{Validation:} Pydantic schema validation (\texttt{DistractorSet}, \texttt{Critique}); negative-stem guard; stem character ceiling.
    \end{itemize}

    \item \textbf{Qwen2.5-VL-7B-Instruct \& 3B-Instruct} (\textit{Vision-Language Model})
    \begin{itemize}
        \item \textbf{Role:} Textbook diagram/figure visual captioning (\texttt{src/captioning/qwen\_vl.py}), full-page OCR transcription (Thread B), and exam PDF question extraction.
        \item \textbf{Configuration \& Hyperparameters:}
        \begin{itemize}[itemsep=1pt,topsep=1pt]
            \item \textit{Precision \& Placement:} \texttt{torch.bfloat16}; two-stage load (CPU $\to$ MPS/CUDA) bypassing Apple Silicon MPS fp16 kernel crashes; lazy instantiation with explicit garbage collection and cache clearance (\texttt{torch.mps.empty\_cache()}).
            \item \textit{Visual Captioning:} $\text{max\_new\_tokens} = 512$, deterministic greedy decoding ($\text{do\_sample} = \text{False}$), grounded with MinerU OCR labels.
            \item \textit{Page Transcription:} $\text{max\_new\_tokens} = 2048$, $\text{max\_pixels} = 1{,}280{,}000$ (~1.28M px) bounding vision prefill token overhead on MPS.
            \item \textit{Image Relevance:} $\text{max\_new\_tokens} = 5$, $\text{max\_pixels} = 480{,}000$, single-token classification (\texttt{SEMANTIC} vs.\ \texttt{DECORATIVE}).
        \end{itemize}
        \item \textbf{Validation:} Visual grounding against MinerU OCR text labels; single-word relevance classification output validation.
    \end{itemize}

    \item \textbf{scispaCy \& NegEx} (\textit{Biomedical NER \& Negation Detection})
    \begin{itemize}
        \item \textbf{Role:} Stage~2 entity recognition and negation detection (\texttt{medkg/stage2\_extract.py}).
        \item \textbf{Configuration:} Multi-model pipeline (\texttt{en\_ner\_bc5cdr\_md} for diseases/chemicals, \texttt{en\_ner\_bionlp13cg\_md} for anatomy/cells/proteins); \texttt{AbbreviationDetector} and \texttt{Negex} over all entity types; longest-span-first entity merging.
        \item \textbf{Validation:} Cross-model span deduplication; ontology label mapping per \texttt{NER\_LABEL\_MAPS}.
    \end{itemize}

    \item \textbf{all-MiniLM-L6-v2} (\textit{Sentence Transformer})
    \begin{itemize}
        \item \textbf{Role:} Semantic boundary chunking of unified text streams (\texttt{src/ingestion/semantic\_chunk.py}).
        \item \textbf{Configuration:} Cosine distance threshold calculated at the $95.0$ percentile over each document; hard fallback split at 6000 characters.
        \item \textbf{Validation:} Distributional percentile adaptation per textbook writing style.
    \end{itemize}

    \item \textbf{Bayesian Knowledge Tracing \& Spaced Repetition Algorithms} (\textit{Probabilistic \& Cognitive Models})
    \begin{itemize}
        \item \textbf{Role:} Real-time student mastery tracking and personalized quiz/flashcard review scheduling (\texttt{src/quiz/}, \texttt{src/flashcards/}, \texttt{BKTStore.swift}).
        \item \textbf{Configuration \& Hyperparameters:}
        \begin{itemize}[itemsep=1pt,topsep=1pt]
            \item \textit{BKT Engine:} 2-state Hidden Markov Model running on-device in Swift with bootstrap priors: $p_{\text{init}} = 0.30$, $p_{\text{transit}} = 0.10$, confidence-conditional slip $p_{\text{slip}}$ (0.05 confident / 0.10 unsure / 0.30 guessing), and guess $p_{\text{guess}}$ (0.10 confident / 0.25 unsure / 0.50 guessing); synced via \texttt{PUT /quiz/mastery} to Neo4j.
            \item \textit{Spaced Repetition (Quiz):} Confidence-weighted interval progression on \texttt{(:Student)-[:REVIEWING]->(:Question)}: correct + confident doubles interval ($1 \to 2 \to 4 \to \dots \le 60\,\text{days}$); wrong or unsure resets streak to 0 (interval 1 day).
            \item \textit{Spaced Repetition (Flashcard):} 4-point rating schedule on \texttt{(:Student)-[:HAS\_FLASHCARD]->(:Flashcard)}: \textit{Again} (0.0 / 1 day), \textit{Hard} ($1.2\times$), \textit{Good} ($2.0\times$), \textit{Easy} ($2.5\times$), capped at 60 days.
        \end{itemize}
        \item \textbf{Validation:} Empirical ROC-AUC next-step prediction evaluation ($0.6819$) and review interval convergence monitoring.
    \end{itemize}
\end{itemize}\par}


\subsection*{Conclusion}

\begin{itemize}
    \item \textbf{Final system architecture:}
          MinerU PDF extraction $\rightarrow$ \texttt{post\_process\_book} cleaning
          (\texttt{.cleaned.md} + \texttt{.page\_map.json}) $\rightarrow$
          \texttt{document-rewriter} (HuatuoGPT-o1-72B tagging) $\rightarrow$
          \texttt{medkg} Stages 1--8 (parse $\rightarrow$ NER $\rightarrow$ entity linking
          $\rightarrow$ relation extraction $\rightarrow$ post-coordination $\rightarrow$
          RDF assertion $\rightarrow$ OWL-RL reasoning $\rightarrow$ N-Quads) $\rightarrow$
          Qwen3.5-27B MCQ generation pipeline. A decoupled FastAPI serving layer reads
          from PostgreSQL (\texttt{mcq\_questions} table) and logs student interaction graphs
          in Neo4j, with \textbf{zero GPU/PyTorch runtime dependencies} in the live API.

    \item \textbf{Why it performs best:}
    \begin{itemize}
        \item \textit{Decoupled architecture:} The live API is fully CPU-bound; all heavy
              inference runs offline during ingestion and generation.
        \item \textit{High quality control:} Every served question passes strict Pydantic
              schema validation and the self-critique correction loop before being committed
              to the database.
        \item \textit{Graph-based student tracking:} Neo4j enables real-time spaced repetition
              and Bayesian Knowledge Tracing (BKT) based on per-topic mastery edges.
    \end{itemize}

    \item \textbf{Comparison with alternative approaches:}
    \begin{itemize}
        \item \textit{Single-pass LLM question generation:} Replaced by the 6-step triple
              extraction $\rightarrow$ distractor generation $\rightarrow$ self-critique pipeline
              to eliminate answer leakage and reduce hallucination in generated stems.
    \end{itemize}

    \item \textbf{Final performance metrics:}
    \begin{itemize}
        \item \textit{BKT knowledge tracing validation:} Next-step correctness prediction evaluated on student interaction trajectories achieved an empirical \textbf{ROC-AUC of 0.6819} and a log-loss of \textbf{0.7105}, confirming its effectiveness in tracking evolving concept mastery and surfacing student knowledge gaps.
        \item \textit{Question bank coverage:} Total of \textbf{188 validated MCQs} generated and structured across three cognitive difficulty tiers.
        \item \textit{Automated critique refinement:} \textbf{62\% (116 of 188 questions)} successfully refined via the self-critique verification loop.
        \item \textit{Ingestion throughput:} \texttt{post\_process\_book} cleaner executes deterministically in sub-second time per PDF chapter.
    \end{itemize}
\end{itemize}
